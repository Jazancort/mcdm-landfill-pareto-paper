## Regras Gerais

> Colar sempre, antes de qualquer ronda.

- **R1** — Uma ronda por sessão. Um commit por ponto. Mensagem num ficheiro: `git commit -F msg.txt`. Nunca usar `git stash` (usar `git show HEAD:ficheiro` ou `git worktree`).
- **R2** — Exit codes (Windows cmd): correr SEMPRE assim, numa só chamada:
  ```
  cmd /v:on /c "mingw32-make check & echo EXIT=!ERRORLEVEL!"
  ```
  Proibido `%ERRORLEVEL%` na mesma linha, pipes (`| findstr`, `| tee`) e redireccionamento nos comandos cujo exit code se reporta. "make check" quer dizer `mingw32-make check`, nunca um script solto.
- **R3** — Nenhum número escrito à mão em `.tex`. Cada número do texto vem de uma macro gerada por um script. Cada ficheiro `macros*.tex` tem um cabeçalho `% generated by <script> from <input> sha256=<...>`.
- **R4** — Resultados selados são intocáveis. No fim de cada ronda:
  ```
  git diff stage4-results-sealed -- results/santiago/mc_*_raw.csv
  git diff stage4-e1fix2-sealed -- results/santiago/mc_*_e1_fix2.csv
  git diff prespec-santiago-f0-amend-final -- corpus/PRESPEC_SANTIAGO*.md
  ```
  Os três têm de sair vazios. Qualquer desvio → registo `DEV-*` em `corpus/deviations/`, nunca editar a pré-especificação.
- **R5** — Condições de PARAGEM: se uma se verificar, parar, reportar e esperar instruções. Não improvisar uma alternativa.
- **R6** — Não usar `grep`/`head` (Windows). Usar Python para ler ficheiros. `PYTHONIOENCODING=utf-8` quando correr scripts diretamente.
- **R7** — Não inventar referências, valores, DOIs nem requisitos de revistas. Se faltar informação, dizer "não verificado".
- **R8** — RELATÓRIO FINAL obrigatório em cada ronda:
  - a) `git status --porcelain` (antes de começar e no fim)
  - b) `git log --oneline -10` e `git show --stat` de cada commit
  - c) output COMPLETO de `make paper` e `make check`, com `EXIT=`
  - d) output dos testes negativos pedidos, com `EXIT=`
  - e) os três `git diff` da regra R4
  - f) lista do que NÃO foi feito e porquê
  - g) `corpus/STATUS.md` e `corpus/SCORECARD.md` atualizados

  Não escrever "feito" sem a evidência correspondente.

## Scorecard — o que significa "nota 9" (`corpus/SCORECARD.md`)

> Cada critério recebe 0–10 com evidência anexada (output, ficheiro, commit). Sem evidência, a nota é 0. A nota final é a média e nenhum critério pode ficar abaixo de 8.

| C10 | Pacote de submissão completo para a revista-alvo | R11 |

**Nota ≥ 9** = média ≥ 9 **E** todos ≥ 8 **E** `make check EXIT=0` **E** selados intactos. A nota do agente é provisória: só conta depois de eu rever.

## Como usar

1. Em cada sessão: cole as **Regras Gerais** e **uma só ronda**. Não junte rondas.
2. **Ordem obrigatória**: 1F e 2a antes de todas as outras. Sem elas, nenhum "exit 0" serve de prova. A partir da Ronda 3 a ordem pode mudar. A 5 (Santiago) pode correr ao mesmo tempo que a 4.

4. **O que só você pode decidir**: a revista-alvo e a confirmação Qualis (Ronda 11), referências novas (Ronda 9) e o que fazer com o `stage1_worktree`. O plano trava o agente nesses pontos.
