## Root cause: SAW/vector scoring difference

The κ=50 macros in Table 5 were generated by `mc_2cube_and_4thcell.py`:

```python
# mc_2cube (WRONG for cost criteria):
return ((X_via / norms) * w).sum(1)   # uses raw X_via
```

The E7 and mc_unified use `scoring.make_scorers()`:

```python
# scoring.py (CORRECT):
return ((X_adj / norms_via) * w).sum(1)  # uses benefit-adjusted X_adj
```

`X_adj_j = 1 - X_via_j` for cost criteria (perm, slope, roads, rivers, coast, wells).
For vector normalisation, cost criteria must be benefit-adjusted before dividing by the
column norm, otherwise high raw values for cost criteria would INCREASE the SAW score.

## Cross-check at κ=200

Both pipelines give **identical** κ=200 Q2 values (86.0, 66.2, 94.4, 63.4, etc.).
At κ=200 (concentrated weights), the benefit-adjustment does not change which trio is
selected by greedy assembly for this dataset. At κ=50 (dispersed weights), it does —
particularly for TOPSIS/vector cells (+4.6 to +5.8 pp difference).

mc_2cube's objectives are computed correctly (per-draw via `compute_objs_ref(w, df_via)`).
Only the SAW/vector scoring is affected.

## Problem

E7 v1 (first run, 2026-10-30) used `seed = BASE_SEED + κ = 100 + 50 = 150` for κ=50.

The PRESPEC §2 specified that κ=50 reuse the existing seed. The existing seed for κ=50
is **seed=42**, identical to κ=200, because `mc_2cube_and_4thcell.py` creates a fresh
`np.random.default_rng(42)` for each α value in sequence:

```python
SEED   = 42
ALPHAS = [50, 200]
for alpha in ALPHAS:
    rng = np.random.default_rng(SEED)   # fresh per alpha
    ...
    w = rng.dirichlet(alpha * w_ahp)
```

So `W_k50 = np.random.default_rng(42).dirichlet(50 * w_ahp, size=500)` and
`W_k200 = np.random.default_rng(42).dirichlet(200 * w_ahp, size=500)` — same seed,
different concentration parameter.
