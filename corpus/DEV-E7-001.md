## Root cause: SAW/vector orientation

The scorer difference for SAW/vector:

```python
# mc_2cube (does NOT apply benefit orientation for vector SAW):
return ((X_via / norms) * w).sum(1)   # cost criteria: high X_via_j = HIGH score (wrong)

# scoring.py (applies orientation as §4.3 requires):
return ((X_adj / norms_via) * w).sum(1)  # cost criteria: 1-X_via_j → high cost = LOW score (correct)
```

§4.3 states: "we adopt orientation after forming the norm" (orientation applied after computing the L2 norm).
scoring.py implements this correctly. mc_2cube does NOT apply orientation for SAW/vector.

Both pipelines give ρ_perm = 0.583 because the amplitude (range/norm) is orientation-invariant:
`range(X_adj)/||X_via_MM|| = range(X_via_MM)/||X_via_MM||` when `range(1-x) = range(x)`.

**At κ=200: same portfolios in both pipelines** — the orientation error does not change the
greedy selection for this dataset at κ=200 (the most heavily weighted criteria are benefit
criteria, so they are unaffected by the orientation difference).

**At κ=50: different portfolios for SAW/vector** — with more dispersed weights, draws occasionally
put high weight on cost criteria (perm, slope, roads), where the orientation difference matters.
