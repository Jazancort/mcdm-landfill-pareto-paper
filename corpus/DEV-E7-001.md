## Resolution: why Table 5 is correct despite D2

The diagnosis in Part 2 compared `mc_2cube_and_4thcell.py` (original, has bug) vs `scoring.py`.
These differ. But **the macros came from `mc_2cube_fixed.py`**, not from the original script.

`mc_2cube_fixed.py` (line 88) uses:
```python
def saw_sc(w, norm="minmax"):
    ...
    else:  # vector: X_adj/norms (benefit-adjusted), consistent with wp3_mc_fixed
        return ((X_adj / norms_via) * w).sum(1)
```

This is identical to `scoring.py`. `mc_2cube_fixed.py` also uses `pareto_utils.is_dominated`
(float64, self-excluded) for Q2 checks. The macros.tex confirms:

```
% ── Q2 per cell at κ=50 (verified from mc_2cube_fixed_raw.csv 2026-10-30) ────
```

Therefore:
- `mc_2cube_and_4thcell.py` has an orientation bug (X_via instead of X_adj for SAW/vec)
- `mc_2cube_fixed.py` already corrects this bug (uses X_adj, same as scoring.py)
- Table 5 SAW/vec values (77.0% greedy, 79.4% optimal at κ=50) came from mc_2cube_fixed.py
- scoring.py with seed=42 gives EXACTLY 77.0% and 79.4% (confirmed by diagnose_q2_rates.py)

**No macro changes are needed.**

## Root cause of Gate G1 failure at κ=50

E7 v1 and v2 were run on Athena with an old version of the script that used seed=43 for κ=50
instead of loading `e1_weights_k50.npy` (seed=42). With seed=43, scoring.py gives different
Q2 values from Table 5 → Gate G1 fails.

Fix applied (2026-11-01):
- `run_e7_kappa_sweep.py` docstring corrected (seed=42, not 43)
- Added `DATA_SHA_K200` and `DATA_SHA_K50` constants (data-byte SHA256)
- Added data SHA assertion after loading each weight matrix:
  ```
  loaded draws_k50  SHA=8b91cba2...  (data OK)
  ```
- Script will fail immediately if wrong draws are loaded
